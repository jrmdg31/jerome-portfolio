# Jerome David — Portfolio

This is my personal portfolio website.

I built this to have a place where I can show what I actually do, the systems I've built, the tools I work with, and some of the projects I've worked on.

It's also a project I use to experiment with frontend development, animation, interaction design, and different ways of presenting my work online.

## How I Work

I generally break projects down into four stages:

```text
01  DISCOVERY

Understand what is currently happening,
what is taking too much time,
and where the problems are.

        ↓

02  MAPPING

Break the workflow down and figure out
what should happen, when it should happen,
and what can be improved.

        ↓

03  BUILD & EXECUTE

Actually build the system and put it
into use.

        ↓

04  OPTIMIZE

Look at what is working, remove unnecessary
steps, and improve the system over time.
```

I don't believe automation should be added just because something *can* be automated.

It should solve an actual problem.

## Running the project locally

Clone the repository:

```bash
git clone https://github.com/jrmdg31/jerome-portfolio.git
```

Move into the project:

```bash
cd jerome-portfolio
```

Install the dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Build the project:

```bash
npm run build
```

Run the production build:

```bash
npm run start
```

Run ESLint:

```bash
npm run lint
```

## Why I built it this way

I wanted the portfolio to demonstrate the same things I tell clients I can do.

If I say I care about systems, the website should have structure.

If I say I care about automation, the interactions shouldn't feel completely static.

If I say I care about details, the small details should actually be there.

And if I say I can learn new technology, the portfolio itself should show that I'm constantly experimenting with it.

So this website is also a project in its own right.
